# 宿舍管理

前端对"宿舍排房"业务域的呈现：从物理资源（区域/楼栋/房间/床位）、住宿申请与订单、排房与调房，到结算阶段的部门费用分摊。后端 `gths-admin` 仓库维护自己的一份 `CONTEXT.md`，两份文档独立维护，不完全一致的地方在下文标注。

## 物理资源

**区域**:
宿舍资源的顶层分组，绑定时区和结算币种，同一区域下辖多栋楼栋。
_Avoid_: 基地、园区

**楼栋**:
区域下的一栋建筑，包含若干楼层。
_Avoid_: 宿舍楼、大楼

**楼层**:
楼栋下的一层，包含若干房间。
_Avoid_: 层

**房间**:
楼层下可容纳一人或多人入住的空间，有房型（单人间/多人间）和容量。
_Avoid_: 宿舍

**床位**:
房间内可被一个住宿人在一个时间段内独立占用的住宿资源。
_Avoid_: 房间容量名额

## 申请与订单

**住宿申请**:
员工发起、走 BPM 审批流程的入住诉求，记录申请人、期望入住区间和目标楼栋。
_Avoid_: 住宿订单（见下方"住宿订单"词条区分）

**住宿订单**:
住宿申请审批通过后生成的履约实体，与申请一对一对应，但拥有独立的履约状态机（待分配/已预订/已取消/已结算/已分摊）。
_Avoid_: 房间订单、床位订单

**住宿人**:
住宿订单下每个入住人的一条记录（前端实现为 `DormSubOrder`），是排房、调房、住宿期变更等操作的操作对象；新排房系统里的 `guestId` 即此记录的 ID。
_Avoid_: 用户、申请人、子订单

**住宿人归属部门**:
住宿人在申请时声明自己所属的部门，仅作为后续结算分摊的参考依据，不等同于实际分摊结果。
_Avoid_: 结算部门、实际分摊部门

## 排房

**排房工作台**:
某楼栋在指定日期区间内的房态、床位与待排房住宿人的聚合视图，是排房操作的入口。
_Avoid_: 排房日历（仅指工作台的日历展示形式）

**待排房住宿人**:
已通过申请审批、但尚未完成床位分配的住宿人，可能与其他住宿人共属同一"申请同住组"，排房时允许拆分。
_Avoid_: 待入住住宿人

**排房草稿**:
宿管在排房工作台上尚未确认提交的一组拟定床位安排，仅存在于前端本地状态，不产生正式占用。
_Avoid_: 临时预订

**床位安排**:
住宿人在一个连续时间段内占用某一床位的记录，操作类型区分初始排房（INITIAL）与调房（TRANSFER）。
_Avoid_: 入住状态、房间状态

**调房**:
从指定生效时间起结束原床位安排并建立新床位安排的操作，原安排仍作为历史保留。
_Avoid_: 删除后重排

**住宿期变更**:
住宿人完成首次排房后，对计划入住/离开时间进行延期或提前退宿的操作，不涉及更换床位。
_Avoid_: 修改审批时间、直接改订单日期

## 结算

**费用分摊**:
对一批已结算的住宿订单，按部门比例或金额拆分实际费用的操作；与住宿人在申请时声明的归属部门不必一致。
_Avoid_: 归属部门、部门标签
