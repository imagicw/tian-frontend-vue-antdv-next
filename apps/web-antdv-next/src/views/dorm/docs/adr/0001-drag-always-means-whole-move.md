# 排房日历拖拽只表达"整体挪动"，中途调房必须走详情弹窗

排房日历的拖拽手势在视觉上呈现的是"把这一整块从这里挪到那里"，用户会预期结果和落点完全一致。但如果把跨床位拖拽的落点日期解释成"调房生效日"（原实现的做法），实际结果是原床位只留到生效日、退宿日仍是原来的日期——和拖拽时视觉呈现的新位置不一致，产生"以为整体移动、结果被拆成两段"的错觉，只能靠确认弹窗里的文字提醒去补救。

改为：拖拽（不管落点是否跨床位）永远表示"整段整体挪到新位置"，对应"重新排房"操作，所见即所得；会产生历史分段、只挪动生效日之后床位的"调房"，只能通过详情弹窗里需要用户主动选择生效日期的操作触发，不再由拖拽落点推断。当住宿人已不满足"重新排房"的可用前提（生效记录跨过不同房间/床位，见 `gths-admin` ADR-0005）时，日历直接禁用其拖拽手势并提示原因，而不是允许拖动、事后报错。
